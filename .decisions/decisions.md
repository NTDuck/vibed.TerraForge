# Decision Log — TerraForge mockup

Every architectural decision, its source (assignment / whiteboard / user rule), and the rejected alternative. Traceability contract: code carries `// dec:` comments that reference a `D-<n>` id from this file.

| ID | Decision | Source | Alternatives rejected | Consequence |
|----|----------|--------|----------------------|-------------|
| D-1 | Mockup web prototype, not a live chain | User: "just need mockup web for the prototype" | Hardhat + testnet deploy (slow, wallet friction) | All chain calls run simulated in `store.ts`. Tx records render as if on-chain |
| D-2 | On-chain vs off-chain is a first-class state bit (`Tx.onChain`) | Assignment B2: "Distinguish between on-chain and off-chain functions" | Prose-only distinction | Every ledger row shows a ⛓/off-chain chip. Screenshots for the report |
| D-3 | Smart-contract guards produce revert records (`status: 'reverted'`, `require`/`revert` in `call`) | B2: "enforcement of at least one smart-contract condition" | Only the happy path | Double-license, non-resellable transfer and usage-permit denials produce visible revert rows and toasts |
| D-4 | Verification bands: similarity below 30 pass · 30–50 human review · 50+ reject. Traceability below 80 → audit | Whiteboard §3 ("AI provenance … <30% … <80% … 50% simi") | Single-threshold gate | `src/lib/verification.ts` `assess()`. Unit-tested boundaries |
| D-5 | Buyer flow: fiat (VND: MoMo/ZaloPay/Napas) → backend check → SC issues license + splits | Whiteboard §Buyer column (fiat gateway, backend check, SM executes, license NFT) | Direct crypto-only checkout (Vietnam users mostly fiat) | `src/flow.ts` orchestrates 4 visible steps |
| D-6 | Splits: primary 90/10 creator/platform. Secondary 85/10/5 seller/royalty/platform | Whiteboard ("Receive royalties", assignment Issue 3) | Flat platform fee | `src/lib/royalties.ts`. Remainder-based, so splits always sum exactly |
| D-7 | Rights tiers (Standard/Studio/Remix) with per-right booleans. Usage checks enforced via `LicenseEnforcer.permit` | Assignment Issue 1 (token ownership ≠ copyright ≠ license) | Assume full ownership transfer | `src/lib/license.ts`. Dashboard usage-checker demo |
| D-8 | AI provenance verdict bands + human cultural reviewer queue | Whiteboard ("human cultural reviewer", integrate industry talk) | Pure AI auto-accept | Reviewer role + review screen. Assignment B3 hook |
| D-9 | No framework: hyperscript `h()` + `commit()` store + hash router | User rule: ponytail (minimal). Mockup scope | React/Vite (extra tooling for 6 screens) | `src/ui.ts`, `src/app.ts`. Zero runtime deps |
| D-11 | Simulated delays (600–700 ms) between purchase steps | Whiteboard buyer flow stages (payment → check → issue) | Instant state jump | Visible stage progress. `CONFIG.demoSpeed` scales for tests |
| D-12 | localStorage persistence, fail-closed shape validation | Demo usability across refreshes | Server/session | `src/persist.ts` checks the shape, else fresh state |
| D-13 | State shape versioned (`State.rev`) | Safe future migrations | None | `CONFIG.storeKey` bumps on a breaking change |
| D-14 | Wallet overlay = sign-in (role picker) + balances. Ledger overlay = full tx history | B2 prototype needs: user roles, one meaningful tx | Full MetaMask integration | `screens/overlays.ts`. Escape closes |
| D-15 | Compatibility passport per asset (platforms × formats) | Whiteboard §compatibility passport. Issue 4 | Skip (interop covered in strategy only) | Asset detail shows the passport. Upload form edits it |
| D-16 | `// dec:` inline comments + this log | User rule: traceable decisions | None | Every module header links decisions to code |
| D-17 | Docker two-stage build: Bun compiles the bundle, nginx serves static files | User rule: "users just need to run docker and open website" | `bun run serve` in the container (heavier runtime image) | `Dockerfile` + `nginx.conf`. Users run `docker run -p 8080:80` and open the site |
| D-18 | All English docs, UI strings and code comments follow ASD-STE100 (structural rules, strict mode) | User rule: "ensure every message in code & every docs adhere to it" | No controlled language. Free-form `dec:` comments (rejected — comments are messages in code) | `tools/ste-lint.sh` checks docs + extracted UI strings + extracted comments. The `dec:` prefix and D-id links stay. Wording follows STE |
| D-19 | Theme engine: runtime base16 picker. 339 Tinted Theming schemes + custom `terraforge-tiffany`, default `flexoki-light` | Wave 1 user directive: theme picker in the topbar | Hardcoded single palette (no user choice). CSS-only light/dark toggle (two states, not 340) | `src/theme.ts` applies a scheme as CSS custom properties on `:root`. `src/themes.ts` holds the scheme table. Choice persists in localStorage (`terraforge-theme`). Base16 gives 16 slots, so every scheme drops in with zero per-theme CSS |
| D-20 | Design grammar: AWS-console structure on a dark baseline, Tiffany-blue `#81D8D0` accent | Wave 1 user directive (feedback #110) | Pastel marketing hero (rejected: reads as a landing page, not a console) | `src/tokens.css` maps the accent to base16 slot 0D. Screens read as page header → chip row → filter row → card grid. Works on every base16 scheme |
| D-21 | Fonts: Inter for body and headings, JetBrains Mono for code. Inter substitutes Amazon Ember | Wave 1 user directive. Amazon Ember is license-locked for this use | Self-hosting Ember (license breach). System-ui only (loses the console look) | `src/tokens.css` font tokens. Inter ships under the SIL Open Font License, so the demo stays redistributable |
| D-22 | Chain network: Polygon | Wave 1 user directive (feedback #2). VND checkout fits a low-fee EVM chain | Ethereum mainnet (fee story contradicts the buyer flow). Solana (not EVM, Solidity surfaces in the contracts screen would not match) | `CONFIG.chain.network = 'Polygon'`. Credentials and chips name Polygon. Contract addresses and tx hashes simulate EVM records |
| D-23 | Dual verification layer gates mint: AI provenance + Compatibility Passport run in parallel, both must pass | Wave 1 user directive (feedback #9, #13) | AI verdict alone (interop issue 4 stays unaddressed). Sequential layers (slower demo, no visual parallel story) | `store.ts` blocks mint unless `verification.status` and `verification.compat.status` are both `verified`. Upload shows the compat card with **Run Compatibility check** |
| D-24 | Compatibility criteria model: deterministic per-engine budgets (triangle count, import format, texture rule, download size) | Wave 1 user directive (feedback #14–16) | Random or AI-scored checks (non-deterministic demo). Boolean platform support only (no visible criteria rows) | `src/lib/compatibility.ts` `BUDGETS` + `criteriaFor()`. Each criterion carries the real numbers in its detail string. Same spec + platform always yields the same result |
| D-25 | Resale limit: a resellable license changes hands at most once. Second buyer Minh Vũ (buyer 2) completes the path | Wave 1 user directive (feedback #18) | Unlimited resale (no revert story for the limit). Third persona drop (the buyer1 → buyer2 hand-off loses its one-click demo) | `CONFIG.maxResales = 1`. `LicenseEnforcer.resale` reverts with `resaleLimitReached`. Dashboard transfer select defaults to Minh Vũ, button reads "Transfer to Minh Vũ" |
| D-26 | Reviewer queue cards carry a full preview: gallery, spec mini-table, AI reasons, compatibility findings | Wave 1 user directive (feedback #21) | Title-only queue rows (reviewer decides blind) | `src/screens/review.ts` reuses the asset gallery + `specTable` + `compatFindings` per card. The reviewer sees what the creator and the engines saw |
| D-27 | Ledger renamed **SERSE Audit Ledger**. The newest settled row gets a `now` highlight | Wave 2 user directive (feedback #107, #108) | Keep "⛓ Ledger" title (name says nothing about audit). No highlight (the latest row does not stand out in a long table) | `CONFIG.chain.auditLedger = 'SERSE Audit Ledger'`. Overlay title, dashboard heading and contracts screen button all name SERSE. `overlays.ts` marks the newest settled tx with `.now` |
| D-28 | Asset detail: gallery card + four accordion blocks (Overview open), Blockchain / Settlement Record block with clickable `.addr` buttons that open the SERSE overlay | Wave 2 user directive (feedback #24–104) | Single long page (details drown). Modal-heavy detail (accordion keeps the four blocks scannable without navigation) | `src/screens/asset.ts` renders the gallery (prev/next + thumbs) and the four `.acc` blocks. Contract address and tx hash buttons call `toggleLedger` |
| D-29 | Marketplace scope: environment kits only | Wave 1 user directive (feedback #1, #3) | Six asset kinds (dilutes the two seeded kits and the market filter) | `src/screens/market.ts` filters to `environment`. Seed ships two environment kits (Hue Imperial Court, Bat Trang Pottery Village). Upload keeps the kind list but the market story stays environment-first |
